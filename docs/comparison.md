# SkillForge Comparison

SkillForge builds on the agent-skills foundation but has a different product direction.

## Upstream Foundation

The upstream project focuses on production-grade engineering skills for AI coding agents. Its strength is disciplined software engineering behavior: spec, plan, build, test, review, and ship.

## SkillForge Direction

SkillForge keeps the engineering discipline and adds productized workflow layers.

| Area | Upstream agent-skills | SkillForge |
|---|---|---|
| Core skills | Engineering lifecycle skills | Preserved and extended |
| Commands | Development lifecycle commands | Preserved, then wrapped by recipes |
| References | Engineering checklists | Preserved and reused |
| Primary audience | AI coding agent users | AI builders, consultants, founders, agencies, operators |
| Extra layer | Skills and commands | Recipes, packs, service workflows, business use cases |
| Monetization path | Open-source utility | Productized packs, audits, consulting workflows |

## Initial Differentiators

SkillForge's first layer of differentiation is intentionally practical:

1. **Repo Audit Pack** — turn a codebase into a score, risk list, and branch-by-branch improvement plan.
2. **AI Consultant Pack** — guide discovery, scope control, proposals, and follow-up.
3. **MVP Builder Pack** — turn an idea into a buildable plan and launch checklist.
4. **Business Ops Pack** — map workflows, SOPs, automations, reports, and AI assistant opportunities.

## What SkillForge Should Avoid

SkillForge should not pretend the original work is new. It should clearly credit the upstream project and focus its differentiation on the added workflow and business layers.

SkillForge should also avoid adding vague advice. A SkillForge recipe or pack should produce a useful outcome: an audit, a roadmap, a discovery summary, a task plan, a proposal outline, or an implementation checklist.
